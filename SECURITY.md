# Security policy

## Supported version

Security fixes are applied to the current `main` branch and the production deployment. Historical dataset releases remain available for audit but are not separately maintained application versions.

## Report a vulnerability

Do not open a public issue for a vulnerability or exposed credential.

Use [GitHub private vulnerability reporting](https://github.com/ardjo-s/clean-energy-map/security/advisories/new). Include affected URLs or commits, impact, reproduction steps, and any suggested mitigation. Do not include real credentials or sensitive personal data.

The project aims to acknowledge a report within 7 days, provide an initial assessment within 14 days, and coordinate disclosure after a fix. These are targets, not guarantees.

Good-faith research that avoids privacy violations, data destruction, service disruption, social engineering, and access beyond what is needed to demonstrate the issue is welcome.

## Scope notes

Incorrect public energy data is normally a data-quality issue; use the data-correction form unless the problem exposes secrets, private data, or a security boundary. Upstream source errors remain attributed to the source and are not silently rewritten.
